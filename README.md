# ByteCore — интернет-магазин ПК-комплектующих

Учебный проект: Firebase Firestore + Firebase Authentication, ваниль JS (ES6-модули),
без сборщиков и фреймворков. Тема: **Торговля → Интернет-магазин** (продажа ПК-комплектующих).

## Структура проекта

```
bytecore/
├── html/
│   ├── index.html        Главная страница: каталог, поиск, фильтры, сортировка, пагинация
│   ├── product.html      Страница товара: характеристики, отзывы, похожие товары
│   ├── cart.html         Корзина и оформление заказа
│   ├── profile.html      Личный кабинет: история заказов, мои отзывы, настройки
│   ├── admin.html        Админ-панель: товары, заказы, пользователи, модерация
│   └── seed.html         Разовая загрузка тестового каталога в Firestore
├── css/style.css
├── js/
│   ├── firebase-config.js   ⚠️ впишите сюда свои ключи Firebase
│   ├── auth.js               регистрация/вход/выход, роли, модалка авторизации
│   ├── catalog.js            логика index.html (realtime + пагинация + поиск)
│   ├── product.js            логика product.html (отзывы, рейтинг, корзина)
│   ├── cart.js                логика cart.html (корзина → заказ, транзакция)
│   ├── profile.js             логика profile.html
│   ├── admin.js                логика admin.html (CRUD, модерация, статистика)
│   ├── icons.js                SVG-иконки товаров по категориям (без внешних картинок)
│   └── utils.js                 общие хелперы (формат цены, тосты, debounce...)
├── data/seed-products.js    50 тестовых товаров во всех 11 категориях (в т.ч. готовые ПК)
├── firestore.rules           правила безопасности
└── firestore.indexes.json     составные индексы, нужные запросам приложения
```

`css/`, `js/` и `data/` остаются на верхнем уровне и никуда не переносятся — все страницы
в `html/` ссылаются на них через `../css/...`, `../js/...`, `../data/...`.

## Про картинки товаров

У 13 товаров (процессоры, материнские платы, память) сразу стоят **настоящие фотографии**
с Pexels (бесплатная лицензия, коммерческое использование разрешено без указания автора) —
поле `imageUrl` в `data/seed-products.js`. Остальные товары показывают SVG-схему компонента
по категории (`js/icons.js`), подобранную под цветовую гамму категории — так у каждого товара
есть картинка, даже если реального фото под рукой не было.

**Добавить фото любому товару вручную:** в админ-панели при создании/редактировании товара
есть поле «Ссылка на фото товара» — вставьте туда прямую ссылку на изображение (свою фотографию,
загруженную в любой хостинг, или Firebase Storage) и сохраните. Если ссылка не открылась —
автоматически показывается SVG-иконка как запасной вариант (`js/utils.js` → `window.__bcImgFallback`).

Осознанно не стал массово подставлять фотографии конкретных брендовых товаров (RTX 4090, Ryzen
и т.д.) из случайного поиска в интернете — такие фото почти всегда принадлежат производителю или
магазину-первоисточнику, и хотлинк на них — это использование чужих защищённых авторским правом
изображений без лицензии. Фото с Pexels/подобных стоков — безопасный вариант именно потому, что
их лицензия явно разрешает такое использование.

## 1. Настройка Firebase

1. Создайте проект на [console.firebase.google.com](https://console.firebase.google.com).
2. **Authentication → Sign-in method** → включите **Email/Password**.
3. **Firestore Database** → создайте базу (production mode).
4. **Project settings → General → Your apps** → добавьте Web-приложение, скопируйте конфиг
   в `js/firebase-config.js`.
5. Установите Firebase CLI и разверните правила/индексы:
   ```bash
   npm install -g firebase-tools
   firebase login
   firebase init firestore   # выберите существующий проект
   firebase deploy --only firestore:rules,firestore:indexes
   ```
   (Либо просто скопируйте содержимое `firestore.rules` в Firestore → Rules в консоли,
   а индексы Firestore подскажет создать сама — при первом запросе, которому не хватает
   индекса, в консоли браузера появится ссылка на автосоздание.)

## 2. Локальный запуск

Статические файлы, поэтому достаточно любого локального сервера (ES-модули не грузятся
через `file://`). Запускайте сервер **из корня проекта** (папка `bytecore`, а не `html`),
чтобы пути `../css`, `../js`, `../data` резолвились правильно:
```bash
npx serve .
# или
python3 -m http.server 5500
```
Откройте `http://localhost:5500/html/index.html` (или тот порт, что покажет `serve`).

## 3. Первый администратор

1. Зарегистрируйтесь на сайте обычным способом (кнопка «Войти» → «Регистрация»).
2. В Firebase Console → Firestore Database → коллекция `users` → найдите свой документ
   (id = ваш uid) → измените поле `role` с `"user"` на `"admin"`.
3. Перелогиньтесь (или обновите страницу) — в шапке появится ссылка «Админ-панель».

## 4. Загрузка тестового каталога

Войдите под аккаунтом администратора и откройте `html/seed.html` → «Загрузить товары в Firestore».
Добавит 50 товаров (`data/seed-products.js`) во всех 11 категориях (включая готовые сборки ПК) с ценами, характеристиками
и остатками на складе.

## Схема базы данных

```
users/{uid}
  name, email, role: "user"|"admin", phone, address, createdAt
  └── cart/{productId}                       (приватная подколлекция, «активные действия»)
        productId, name, price, category, qty, addedAt

products/{productId}                          (основные сущности)
  name, brand, category, price, stock, model,
  description, specs: {ключ: значение},
  keywords: [строки для поиска], rating, reviewCount, createdAt
  └── reviews/{reviewId = authorUid}          («действия» — отзывы)
        userId, userName, rating (1-5), text, createdAt

orders/{orderId}                              («действия» — история заказов)
  userId, userName, items: [{productId, name, price, qty, category}],
  total, address, status: pending|processing|shipped|completed|cancelled, createdAt
```

**Почему так:**
- `cart` — подколлекция внутри `users/{uid}`, а не отдельная коллекция: корзина по своей
  природе принадлежит одному пользователю, и вложенность делает правила безопасности
  тривиальными (`allow read, write: if isOwner(uid)`), а realtime-подписку — точечной.
- `reviews` — подколлекция товара (а не отдельная коллекция с полем `productId`): так
  быстрее всего получить «все отзывы этого товара» без индекса, а `reviewId == uid` даёт
  ровно один отзыв на пользователя без дополнительной проверки в правилах.
- Для «моих отзывов» в личном кабинете используется **collection group query**
  (`collectionGroup(db, "reviews")`), которая ищет по всем подколлекциям `reviews` сразу.
- `orders` — отдельная плоская коллекция (не подколлекция `users`), потому что админ должен
  читать *все* заказы разом для админ-панели — collectionGroup тут был бы избыточен, а плоская
  коллекция с `where("userId","==",uid)` и `where("status","==",...)` проще для индексации.

## Обязательные Firebase-возможности — где реализованы

| Требование | Где |
|---|---|
| `onSnapshot` (realtime) | каталог (`catalog.js`), карточка товара — сток/статус (`product.js`), корзина (`cart.js`), заказы в профиле и админке (`profile.js`, `admin.js`), пользователи и отзывы в админке |
| Пагинация | каталог — растущий `limit()` + кнопка «Показать ещё» (`catalog.js`) |
| Оптимизация запросов | составные `where`+`orderBy` вместо клиентской фильтрации; `getCountFromServer` для статистики вместо загрузки всех документов; `keywords` — денормализованный массив токенов для полнотекстового поиска через `array-contains-any` |
| Правила безопасности | `firestore.rules` — раздельные права `user`/`admin`, запрет самопромоушена в админы, приватная корзина, неизменяемые заказы для обычных пользователей |

## Известные ограничения (для честности при сдаче)

- Пересчёт `rating`/`reviewCount` товара после отзыва делается на клиенте (`recomputeRating`
  в `product.js`), а не Cloud Function-триггером — в задании Cloud Functions не входят в
  обязательный стек, но это единственная точка, где недобросовестный клиент теоретически
  мог бы прислать неверный агрегат. Для реальной продакшн-системы это стоит вынести на бэкенд.
- Убывание `stock` при оформлении заказа выполняется в `runTransaction`, что защищает от
  overselling при параллельных заказах, но отмена/восстановление стока при `status: cancelled`
  не реализовано — при необходимости добавьте это в `admin.js` при смене статуса на «Отменён».
